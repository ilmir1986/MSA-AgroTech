### **Название задачи:**
Сравнение архитектурных решений MVP-системы мониторинга свиноводческих ферм и выбор оптимального варианта

### **Автор:**
Бурганов И.И.

### **Дата:**
12 января 2026 г.

### **Функциональные требования**

| № | Действующие лица или системы | Use Case | Описание |
| :-: | :- | :- | :- |
| 1 | Оператор фермы | Получение оповещений о нештатных ситуациях | Система должна уведомлять оператора при признаках драк, задавливания поросят, гибели животных и т.п. |
| 2 | Ветеринарный врач | Мониторинг состояния поголовья | Получение уведомлений о болезнях, аномальном поведении, смертности |
| 3 | Администратор системы | Управление пользователями и ролями | Настройка доступа, ролей, интеграция с IAM |
| 4 | Руководитель хозяйства | Просмотр аналитики и KPI | Получение отчётов по эффективности кормления, поголовью, расходу ресурсов |
| 5 | Фермерские комплексы (агенты) | Отправка телеметрии | Передача видео, данных с датчиков, статусов оборудования |
| 6 | Фермерские комплексы (агенты) | Приём управляющих команд | Выполнение команд на включение/отключение кормушек, поилок и т.д. |
| 7 | Система | Автономная работа на ферме | Обеспечение работы при отсутствии интернета и последующая синхронизация |
| 8 | Система | Интеграция с внешними сервисами | Предоставление API для мобильных и веб-приложений |

### **Нефункциональные требования**

| № | Требование |
| :-: | :- |
| 1 | Отказоустойчивость 99,95% |
| 2 | Время реакции на нештатную ситуацию ≤ 5 секунд |
| 3 | Видеоаналитика — реагирование в реальном времени (мс) |
| 4 | Поддержка offline-режима на ферме до 10 минут без потери данных |
| 5 | Расширяемость — возможность добавления новых метрик и модулей без переработки ядра |
| 6 | Совместимость с камерами разных производителей |
| 7 | Безопасность — поддержка современных методов аутентификации и авторизации (OAuth2 / OpenID Connect) |
| 8 | Горизонтальная масштабируемость для будущего SaaS-развёртывания |

### **Критерии сравнения решений**

Для объективного выбора между **основным** и **альтернативным** решениями определены следующие критерии:

| Критерий | Описание |
| :- | :- |
| **Скорость запуска MVP** | Время до первого рабочего прототипа на реальных фермах |
| **Техническая независимость** | Зависимость от существующих систем и команд |
| **Производительность и latency** | Соответствие требованиям ≤5 сек на реакцию и обработка видео в реальном времени |
| **Offline-поддержка** | Надёжность работы при отсутствии связи |
| **Безопасность и изоляция** | Возможность реализовать RBAC и изоляцию по фермам |
| **Поддержка SaaS-эволюции** | Готовность архитектуры к мультитенантности |
| **Операционная сложность** | Сложность развёртывания, мониторинга, обновления |
| **Общая стоимость владения (TCO)** | Инфраструктурные и трудовые затраты на 6–12 месяцев |

### **Анализ решений по критериям**

| Критерий | Основное решение                                              | Альтернативное решение                                                   |
| :- |:--------------------------------------------------------------|:-------------------------------------------------------------------------|
| **Скорость запуска MVP** | **Высокая** (6–8 недель). Нет зависимостей от других команд.  | **Низкая** (+3–4 недели). Требуется согласование с `АгроПром X`.         |
| **Техническая независимость** | **Полная**. Собственный Kafka, БД, IAM.                       | **Зависимость** от инфраструктуры и SLA `АгроПром X`.                    |
| **Производительность и latency** | **Гарантирована**. Видеоаналитика на edge, Kafka выделен.     | **Риск**. Централизованная Kafka может стать узким местом.               |
| **Offline-поддержка** | **Реализована явно**. Локальное хранилище + буферизация.      | **Частичная**. Требует доработки существующей шины.                      |
| **Безопасность и изоляция** | **Полная**. Keycloak с RBAC по фермам.                        | **Ограничена**. Единый IAM без изоляции клиентов.                        |
| **Поддержка SaaS-эволюции** | **Готова**. Архитектура multi-tenant ready.                   | **Не поддерживается**. Требуется полная переработка.                     |
| **Операционная сложность** | **Средняя**. Новый стек, но стандартный (K8s, Kafka, Spring). | **Низкая** (на первый взгляд), но скрытые зависимости увеличивают риски. |
| **Общая стоимость владения (TCO)** | **Выше на 15–20%** из-за дублирования инфраструктуры.         | **Ниже** за счёт reuse, но с риском hidden costs.                        |

---

### **Резюме и рекомендация**

**Рекомендуется выбрать основное решение**, несмотря на немного более высокий TCO.

**Обоснование:**
- **MVP должен быть быстрым, предсказуемым и независимым**.
- **Offline-режим и latency** — критически важны для ферм.
- **SaaS-перспектива** — бизнес рассматривает платформу как новый источник дохода. Архитектура должна быть готова к мультитенантности с самого начала.
- **Технический долг** — альтернативное решение создаёт долг, который будет сложно погасить при масштабировании.
